# Руководство пользователя

[← README](../README.md) · [Настройка](CONFIGURATION.md) · [Архитектура](ARCHITECTURE.md)

Управление OBS Control осуществляется **в личном чате Telegram** через команды и кнопки. Команда `/help` открывает такое же меню, как `/start` и `/menu`.

## Начало работы администратора

1. Отправьте `/start` — бот распознает ID первоначального администратора из `.env`.
2. В `/obs` заполните адрес, порт и пароль OBS WebSocket. При необходимости используйте `/empty_password`, но режим без пароля не рекомендуется.
3. Нажмите **«Проверить связь»** и убедитесь, что OBS отвечает.
4. Откройте `/setup` и выберите Browser Source, основную сцену и сцену паузы. Они должны относиться к одной активной коллекции; сцены не должны совпадать.
5. Выполните **«Проверить назначения»**, затем `/snapshot` и `/check`, чтобы увидеть фактический кадр и результат анализа.
6. Настройте нужные детекторы в `/rules`. Если нужен контроль зависания или однотонного кадра, **включите его отдельно** — исходно они выключены.
7. Сделайте основную сцену текущей в OBS. Откройте `/auto` → «Включить» или отправьте `/auto on`.
8. Посмотрите `/status`, а затем проверьте, переключается ли трансляция при предусмотренном вами тестовом проблемном кадре.

При нажатии «Выключить» или команде `/auto off` бот отключит автоматическое управление сценами; он **не обязан возвращать сцену** на основную. Её можно выбрать вручную через `/scenes` или в OBS.

## Права доступа

| Действие | `viewer` | `operator` | `admin` |
| --- | :---: | :---: | :---: |
| `/status`, `/menu` | ✓ | ✓ | ✓ |
| Ручной выбор сцен, изменение видимости элементов сцены | — | ✓ | ✓ |
| `/check`, `/snapshot`, обновление Browser Source | — | ✓ | ✓ |
| Включение/выключение автоматики | — | ✓ | ✓ |
| Настройка подключения, назначений и правил | — | — | ✓ |
| Выбор профилей/коллекций OBS | — | — | ✓ |
| Управление трансляцией OBS | — | — | ✓ |
| Настройка уведомлений и управление доступом | — | — | ✓ |

Команда `/id` доступна **даже неавторизованным** пользователям, но только в личном чате. Неавторизованный пользователь может открыть `/start` и отправить заявку на доступ через кнопку или `/request_access`.

## Команды

### Общие

| Команда | Назначение |
| --- | --- |
| `/start`, `/help`, `/menu` | Открыть главное меню или экран заявки для пользователя без доступа. |
| `/id` | Показать собственный Telegram ID (в личном чате). |
| `/status` | Текущая информация о соединении, OBS-профиле, сцене, трансляции, назначениях, детекторе и ошибках. |
| `/cancel` | Отменить текущий диалог ввода адреса/пароля или добавления пользователя. |
| `/request_access` | Отправить заявку администратору, если доступа ещё нет. |

### Оператор и администратор

| Команда | Назначение |
| --- | --- |
| `/scenes` | Выбрать сцену OBS вручную. **Отключает автоматику.** |
| `/sources` | Посмотреть элементы **текущей сцены** и переключать их видимость. |
| `/check` | Выполнить одноразовый анализ кадра контролируемого Browser Source. |
| `/snapshot` | Получить PNG-снимок контролируемого Browser Source. |
| `/auto` | Показать кнопки включения/выключения автоматики. |
| `/auto on` | Включить мониторинг после проверки назначений и текущей основной сцены. |
| `/auto off` | Выключить автоматику. |
| `/refresh` | Принудительно обновить **назначенный** Browser Source без кеша. |
| `/refreshsources` | Выбрать Browser Source из текущей коллекции для обновления, включая возможность обновить все источники с подтверждением. |

`/check` не меняет сцену и анализирует **один кадр**; подтверждение зависания требует нескольких последовательных кадров в работающем мониторинге. `/snapshot` отправляет картинку, но не включает автоматику.

### Только администратор

| Команда | Назначение |
| --- | --- |
| `/obs` | Настроить подключение к OBS WebSocket и проверить связь. |
| `/setup` | Выбрать Browser Source, основную сцену, сцену паузы; проверить назначения. |
| `/rules` | Включить/выключить типы проверок, выбрать предустановленные пороги и аудиоисточник. |
| `/setrule <ключ> <число>` | Установить точное значение числового параметра детектора. |
| `/notifications` | Настроить время жизни временных push, антиспам и очистку уведомлений. |
| `/setnotify <ключ> <секунды>` | Ввести точные числовые параметры уведомлений. |
| `/profiles` | Вручную выбрать текущий профиль OBS; при фактической смене запрещено во время эфира или записи. |
| `/collections` | Выбрать активную коллекцию сцен OBS. |
| `/stream` | Выбрать профиль для следующего эфира, запустить/остановить вещание с подтверждением. |
| `/users` | Просматривать роли и заявки, добавлять, изменять и удалять доступ. |
| `/grant <id> <роль>` | Выдать доступ `viewer`, `operator` или `admin` пользователю по Telegram ID. |
| `/revoke <id>` | Отозвать доступ по Telegram ID. |
| `/empty_password` | Установить пустой пароль OBS, **только в режиме редактирования пароля** внутри `/obs`. |

Примеры:

```text
/setrule bad_checks 5
/setrule good_checks 2
/setrule freeze_seconds 25
/setrule audio_threshold_db -45
/setnotify ttl_seconds 120
/grant 123456789 operator
/revoke 123456789
```

Полные диапазоны числовых правил и уведомлений приведены в [конфигурации](CONFIGURATION.md).

## Сценарии работы

### Автоматическое переключение по кадру

Для типовой конфигурации с шаблонными параметрами (`interval_seconds=3`, `bad_checks=4`, `good_checks=3`) бот периодически получает кадры источника. Четыре подряд плохие проверки чёрного кадра приводят к переключению на резервную сцену. После трёх подряд хороших проверок бот возвращает основную сцену. Реальная задержка зависит от времени запросов OBS и выполнения проверок; это не фиксированные таймеры. Анализ зависания может переключить сцену сразу при достижении собственного порога времени.

Бот управляет сценой паузы только если **сам переключил OBS на неё**. Если пользователь вручную выбирает другую сцену через бота, автоматика отключается. Если кто-то меняет сцену извне, когда бот уже переключил на паузу, он также отключает автоматику и уведомляет администраторов.

### Обновление зависшего браузерного источника

Откройте `/refreshsources`, выберите конкретный Browser Source либо подтвердите обновление всех Browser Source текущей коллекции. Для этого вызывается команда OBS обновить страницу **без кеша**. Видимость элементов, текущая сцена и состояние автоматики от самого запроса перезагрузки не меняются. На время обновления изображение может исчезнуть.

Команда `/refresh` обновляет **именно отслеживаемый источник**, выбранный в `/setup`, и требует корректных назначений.

### Проверка звука и исключение ложной тревоги

В `/rules` выберите входной аудиоисточник OBS, включите аудиоисключение и настройте `audio_threshold_db` и `audio_hold_seconds`. Во время воспроизведения звука нажмите **«Проверить звук»**. Если источник заглушён, отсутствуют свежие события измерителя или звук не достигает порога, проблемная картинка будет считаться плохой. Аудиоисключение влияет на решение о переключении, но **не исправляет кадр**.

### Трансляция OBS

В `/stream`:

1. Откройте **«Выбрать профиль»** и сохраните OBS-профиль для следующего запуска.
2. Выберите **«Запустить трансляцию»** и подтвердите запуск. Если активный профиль OBS отличается, бот попробует переключиться на выбранный — только когда нет эфира и записи.
3. Проверяйте актуальное состояние кнопкой **«Обновить»**.
4. Для завершения выберите **«Остановить трансляцию»** и подтвердите остановку.

Параметры сервера/платформы и ключ трансляции **настраиваются непосредственно в OBS**, а не в Telegram. При смене профиля OBS бот отключает автоматику мониторинга, которую после этого при необходимости включают повторно.

### Запрос доступа

Новый пользователь пишет боту `/start` и нажимает **«Запросить доступ»**, либо использует `/request_access`. Администраторы получают заявку и могут выдать роль `viewer`, `operator` или `admin` либо отказать. Запросы ограничены повторной отправкой (пауза до **10 минут**) и максимальным количеством ожидающих (**100**).

Администратор может добавить пользователя вручную через `/users` → «Добавить по Telegram ID» или командой `/grant`. Для выдачи роли `admin` через кнопки требуется отдельное подтверждение. Первоначального администратора нельзя удалить или понизить, себя нельзя удалить или понизить через процедуры управления доступом.

## Сообщения о состоянии и уведомления

- Администраторам отправляется отдельное **обновляемое** статусное сообщение; бот пытается закрепить его.
- В нём отображаются режим автоматики, последняя известная сцена, состояние трансляции на момент последней проверки, последний инцидент и число переключений на паузу за текущий день.
- При критических событиях (например, переключении на паузу, недействительных назначениях, ошибке мониторинга) бот отправляет временное уведомление с ограничением частоты. Отправленное сообщение удаляется по таймеру, если Telegram позволяет это сделать.
- События восстановления картинки и запуска/остановки трансляции обновляют статусное сообщение без отдельного временного push.

Чтобы получать сообщения, администратор должен открыть личный чат с ботом; Telegram может не позволить боту инициировать переписку первым.
