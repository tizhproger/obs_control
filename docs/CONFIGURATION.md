# Конфигурация

[← README](../README.md) · [Установка](INSTALLATION.md) · [Использование](USAGE.md)

## Где хранятся настройки

| Файл | Загрузка и назначение |
| --- | --- |
| `.env` | Токен Telegram и ID первоначального администратора. Загружается при запуске. |
| `config.example.json` | Шаблон для первого старта, если нет `settings.json` или старого `config.json`. |
| `settings.json` | Текущие параметры подключения OBS, источники и сцены, настройки уведомлений, пользователи и профиль для запуска эфира. Создаётся автоматически. |
| `state.json` | Включён ли автоматический мониторинг, владеет ли он сценой паузы, и активные параметры детектора. Создаётся при сохранении состояния. |
| `notifications.json` | ID статусных сообщений, счётчик переключений, история событий, ограничения отправки и очередь удаления сообщений. |

Параметры, доступные из Telegram, предпочтительно менять через бот. **Не редактируйте служебные JSON-файлы во время работы программы:** в памяти уже находятся прочитанные значения, а последующее сохранение может перезаписать ручные правки. Для прямого редактирования остановите скрипт.

`settings.json` содержит пароль OBS **открытым текстом**. Исходный `.gitignore` исключает `.env`, `settings.json`, `state.json` и `config.json`, но **не `notifications.json`**. Не коммитьте рабочие данные и следите за правами доступа к ним.

## Подключение OBS

Первоначальные значения в [`config.example.json`](../config.example.json):

```json
"obs": {
  "host": "127.0.0.1",
  "port": 4455,
  "password": ""
}
```

Здесь показан **фрагмент** файла, а не самостоятельный JSON-документ.

В личном чате администратора откройте `/obs` и последовательно задайте:

- **Адрес** — IPv4-адрес или имя узла без схемы `http://` и пути. Для OBS на том же компьютере пример — `127.0.0.1`.
- **Порт** — целое число `1–65535`; обычно используется `4455`.
- **Пароль** — пароль сервера OBS WebSocket. Для пустого пароля в режиме редактирования используется отдельная команда `/empty_password`.

Нажмите **«Проверить связь»**. Бот делает запрос версии OBS; без работающего соединения он не сможет заполнить списки сцен и источников. При изменении любого параметра подключения автоматика выключается, а при фактической смене адреса или порта также сбрасываются назначения источника и сцен.

### Назначения мониторинга

В `/setup` выбираются три объекта из **текущей коллекции сцен OBS**:

| Поле | Назначение |
| --- | --- |
| `monitor.source_name` | Отслеживаемый вход OBS типа `browser_source`. |
| `monitor.normal_scene` | Сцена с нормальным вещанием. |
| `monitor.fallback_scene` | Сцена паузы, на которую переключает бот при проблеме. |
| `monitor.collection_name` | Имя коллекции сцен; назначается автоматически по активной коллекции при выборе объекта. |

Основная и резервная сцены должны быть **разными**. Бот проверяет наличие объектов и совпадение сохранённой и текущей коллекций. Если выбрать объект из другой коллекции, старые назначения сбрасываются. Любое переназначение отключает автоматику; для повторного включения текущая сцена OBS должна совпадать с `normal_scene`.

## Проверки изображения

Бот запрашивает PNG-снимок OBS-источника, переводит его в оттенки серого, применяет обрезку (`crop`) и приводит анализируемую область к `160×90`. При первом запуске по умолчанию **включена только проверка чёрного кадра**.

| Параметр | Значение из шаблона / при инициализации | Описание |
| --- | --- | --- |
| `screenshot_width` | `320` | Ширина запрашиваемого снимка; допустимо `8–4096`. |
| `screenshot_height` | `180` | Высота снимка; допустимо `8–4096`. |
| `crop` | `[0.05, 0.05, 0.95, 0.95]` | Нормализованные координаты `лево, верх, право, низ`, значения `0–1`. |
| `rules.interval_seconds` | `3` | Период проверок в секундах; `1–60`. |
| `rules.bad_checks` | `4` | Сколько плохих проверок подряд нужно для переключения при чёрном/однотонном кадре; `1–100`. |
| `rules.good_checks` | `3` | Сколько хороших проверок подряд нужно для возврата; `1–100`. |
| `rules.black` | `true` | Активирует обнаружение почти чёрного кадра. |
| `rules.black_pixel_threshold` | `25` | Максимальная яркость пикселя, считаемого чёрным (в анализе); `0–100`. |
| `rules.black_fraction` | `0.98` | Минимальная доля таких пикселей для срабатывания; `0.5–1.0`. |
| `rules.uniform` | `false` | Активирует обнаружение однотонного кадра. |
| `rules.uniform_stddev` | `2` | Максимальное стандартное отклонение яркости; `0–50`. |
| `rules.freeze` | `false` | Активирует обнаружение зависшего изображения. |
| `rules.freeze_seconds` | `25` | Время неизменности для срабатывания, секунды; `3–600`. |
| `rules.frame_diff_threshold` | `1.0` | Порог среднего изменения яркости между кадрами; `0–30`. |
| `rules.audio_override` | `false` | Не считать проблемный кадр основанием для переключения при подтверждённом звуке. |
| `rules.audio_threshold_db` | `-45.0` | Минимальный пик измеренного аудиосигнала; `−80…−10` дБ. |
| `rules.audio_hold_seconds` | `8.0` | Временное окно для звукового пика; `1–30` секунд. |

Первые значения берутся из `config.example.json`, дополнительные аудиополя вставляются программой при загрузке. После первого сохранения **активные** правила читаются из `state.json`, поэтому они могут отличаться от исходного шаблона.

### Что происходит при срабатывании

- **Чёрный кадр:** доля пикселей с яркостью не выше `black_pixel_threshold` достигает `black_fraction`.
- **Однотонный кадр:** стандартное отклонение яркости не превышает `uniform_stddev`.
- **Зависание:** средняя разница последовательных кадров не превышает `frame_diff_threshold` в течение `freeze_seconds`. Как только этот порог времени достигнут, переключение на паузу может произойти **без ожидания `bad_checks`**.
- **Возврат:** кадр считается хорошим, когда не сработало ни одно активное правило или проблемный кадр разрешён аудиоисключением. Для возврата с паузы нужны `good_checks` подряд.

Детектор проверяет условия в порядке: чёрный кадр → однотонный кадр → зависание. Это важно для текста причины и для правила немедленного переключения по зависанию.

### Изменение правил из Telegram

В `/rules` доступны переключатели и готовые значения для интервала, количества плохих/хороших проверок, времени зависания и аудиопорогов. Точное числовое значение задаётся администратором командой:

```text
/setrule bad_checks 5
/setrule interval_seconds 2
/setrule black_fraction 0.95
/setrule freeze_seconds 30
/setrule audio_threshold_db -50
```

Команда принимает пары `<ключ> <значение>` только для числовых правил. Логические параметры `black`, `uniform`, `freeze`, `audio_override` переключаются кнопками в `/rules`. После изменения порогов счётчики и состояние сравнения кадров сбрасываются; при смене интервала новый период применяется в работающем цикле мониторинга.

`screenshot_width`, `screenshot_height` и `crop` **не редактируются через Telegram** в данной реализации. Для их изменения остановите приложение, измените раздел `monitor` в `settings.json` и вновь запустите скрипт. Обрезка должна удовлетворять условию `0 ≤ left < right ≤ 1`, `0 ≤ top < bottom ≤ 1`.

### Аудиоисключение

В `/rules` администратор выбирает источник звука OBS и включает переключатель «Разрешить проблемную картинку при звуке». Бот получает события измерителя уровня звука через WebSocket. Чтобы игнорировать плохой кадр, одновременно должны выполняться условия:

1. Включено правило `audio_override` и выбран существующий аудиоисточник.
2. Приходят свежие показатели измерителя именно этого источника.
3. За `audio_hold_seconds` был зафиксирован пик не ниже `audio_threshold_db`.
4. Источник **не заглушён (mute)** в OBS.

Если измеритель недоступен или проверить `mute` не удалось, исключение не применяется. В `/rules` есть кнопка **«Проверить звук»** — она показывает пиковый уровень, наличие событий и причину, по которой правило может не сработать.

## Уведомления

Управление: `/notifications` или командой `/setnotify <ключ> <секунды>`.

| Ключ | По умолчанию | Диапазон | Назначение |
| --- | ---: | ---: | --- |
| `ttl_seconds` | `60` | `10–3600` | Через сколько секунд удалить новое временное push-сообщение. |
| `cooldown_seconds` | `300` | `30–86400` | Минимальный интервал между отправками push одному администратору. |
| `cleanup_interval_seconds` | `5` | `1–60` | Частота проверки очереди удаления сообщений. |

Примеры:

```text
/setnotify ttl_seconds 90
/setnotify cooldown_seconds 600
/setnotify cleanup_interval_seconds 10
```

Всем администраторам бот пытается отправить и закрепить **одно обновляемое статусное сообщение**. При переключении на паузу или ошибках дополнительно отправляется временное push-уведомление (с учётом антиспама). При восстановлении картинки, восстановлении соединения и действиях с трансляцией обновляется статус, но отдельный push не отправляется для событий типов `recovered` и `stream`. Счётчик переключений на паузу ведётся по локальной дате компьютера с ботом.

Уведомления доступны только если Telegram разрешает боту писать адресату, поэтому администратору необходимо предварительно открыть личный чат с ботом.

## Трансляция и профили

Через `/stream` администратор выбирает **профиль OBS для следующего эфира** и подтверждает запуск или остановку трансляции. Выбор не меняет активный профиль до запуска. Если необходимо переключить профиль перед стартом, приложение запрещает это при активной записи; при активной трансляции менять профиль также нельзя. Смена профиля через бот отключает автоматику.

**Важно:** бот не задаёт платформу вещания, сервер и ключ трансляции. Они должны быть заранее настроены в самом профиле OBS.

## Доступ пользователей

Роли хранятся в `settings.json` (`telegram.users`). Первоначальный администратор берётся из `ADMIN_TELEGRAM_ID` и сохраняет роль `admin`. Остальные пользователи могут запрашивать доступ из `/start`; администратор одобряет или отклоняет заявку через `/users`, либо добавляет пользователя вручную по Telegram ID. Подробнее о правах: [руководство пользователя](USAGE.md#права-доступа).
