# Установка и первый запуск

[← README](../README.md) · [Настройка](CONFIGURATION.md) · [Использование](USAGE.md)

## 1. Подготовка

Для запуска необходимы:

- Python **3.10+** с `pip`;
- OBS Studio с работающим интерфейсом **OBS WebSocket**;
- токен Telegram-бота и собственный числовой Telegram ID;
- сетевой доступ от компьютера с ботом к адресу OBS WebSocket и к Telegram.

Бот может работать на том же компьютере, что и OBS, или подключаться к OBS по сети. **OBS должен быть запущен**, а WebSocket должен принимать подключения по указанному адресу и порту. В предоставленном проекте отсутствуют Dockerfile, Compose-файлы и настройки автозапуска в ОС.

## 2. Подготовка OBS

1. В OBS откройте настройки сервера WebSocket и убедитесь, что сервер включён.
2. Узнайте адрес, порт и пароль доступа. В примере проекта используется `127.0.0.1:4455` без пароля; для фактического использования рекомендуется включить аутентификацию WebSocket.
3. В нужной коллекции сцен подготовьте **Browser Source**, **основную сцену** и отдельную **сцену паузы**.
4. Убедитесь, что у источника загружается изображение: бот делает скриншот **самого источника**, а не всей сцены.
5. Если бот запускается на другом устройстве, укажите доступный этому устройству адрес OBS и настройте безопасный сетевой доступ. Не открывайте OBS WebSocket в публичный Интернет.

## 3. Python и зависимости

### Linux / macOS

В терминале, находясь в каталоге с `main.py`:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
```

### Windows PowerShell

```powershell
py -3 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
Copy-Item .env.example .env
```

Если политика PowerShell не позволяет активировать окружение, можно запускать Python напрямую из `.venv\Scripts\python.exe`.

Устанавливаются пакеты из [`requirements.txt`](../requirements.txt): `obsws-python`, `aiogram`, `Pillow`, `python-dotenv`.

## 4. Переменные окружения

Откройте созданный `.env` и заполните:

```dotenv
TELEGRAM_BOT_TOKEN=123456789:actual_token_from_botfather
ADMIN_TELEGRAM_ID=123456789
```

- `TELEGRAM_BOT_TOKEN` — токен, выданный Telegram для вашего бота. Нельзя оставлять значение-заглушку.
- `ADMIN_TELEGRAM_ID` — числовой ID первоначального администратора, которому автоматически назначается роль `admin`. Чтобы узнать ID, отправьте `/id` боту в личном чате: команда не требует авторизации.

Первоначального администратора нельзя удалить или понизить через интерфейс бота. Пример `.env.example` содержит **только заглушки**, использовать их в рабочем запуске нельзя.

## 5. Запуск

```bash
python main.py
```

После запуска откройте личный чат с ботом и отправьте `/start`. При первом старте программа считывает `config.example.json` и создаёт `settings.json`. Файл `state.json` появляется при первом сохранении состояния автоматики или правил; `notifications.json` создаётся при сохранении уведомлений/статуса.

Бот использует Telegram **long polling**. При запуске удаляется ранее установленный webhook и отбрасываются накопленные обновления (`drop_pending_updates=True`). Не запускайте параллельно несколько экземпляров с одним токеном.

Дальнейшая первоначальная настройка выполняется через `/obs`, `/setup` и `/rules`. Пошаговая последовательность описана в [README](../README.md#краткая-инструкция-по-использованию).

## 6. Остановка и повторный старт

Для остановки в терминале используйте `Ctrl+C`. При следующем запуске программа читает сохранённые `settings.json`, `state.json` и `notifications.json`.

Если `settings.json` отсутствует, но присутствует старый `config.json`, его содержимое используется для переноса настройки в `settings.json`. В этом режиме может использоваться прежняя переменная `OBS_WEBSOCKET_PASSWORD` для переноса пароля, но при обычной работе пароль OBS хранится в `settings.json` и меняется через Telegram.

При сохранённом включённом режиме автоматики бот пытается продолжить мониторинг после перезапуска, поэтому перед первым включением убедитесь в корректности назначений.

## 7. Простейшая проверка

1. Команда `/obs` → проверка подключения должна показать версию OBS.
2. В `/setup` проверка назначений должна вернуть подтверждение корректности.
3. `/snapshot` должен прислать изображение выбранного Browser Source.
4. `/check` должен сообщить результат анализа кадра.
5. В OBS включите основную сцену и затем активируйте автоматику через `/auto on`.

Ошибки подключения, назначений и детектора: [диагностика](TROUBLESHOOTING.md).

## Защита конфигурации

`.env`, `settings.json`, `state.json`, `notifications.json` — локальные служебные файлы. Не публикуйте их содержимое. Исходный `.gitignore` не исключает `notifications.json`, поэтому добавьте этот файл в локальные правила исключения Git до публикации или иным способом убедитесь, что он не попадает в коммиты. Ограничьте доступ к `settings.json`: в нём сохраняется пароль OBS WebSocket как строка JSON без шифрования.
