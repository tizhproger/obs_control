# Диагностика и устранение неполадок

[← README](../README.md) · [Установка](INSTALLATION.md) · [Настройка](CONFIGURATION.md)

Начните с `/status`: эта команда показывает состояние OBS, последнее назначение, результат анализа кадра и сообщения об ошибках. Для дополнительной проверки используйте `/obs` → «Проверить связь», `/setup` → «Проверить назначения», `/snapshot` и `/check`.

| Симптом | Возможная причина | Что проверить |
| --- | --- | --- |
| Программа завершилась с сообщением о `TELEGRAM_BOT_TOKEN` | В `.env` нет действительного токена или осталась заглушка | Заполните `TELEGRAM_BOT_TOKEN`; файл `.env` должен лежать рядом с `main.py`. |
| Ошибка `ADMIN_TELEGRAM_ID` при старте | Не указан положительный числовой ID первичного администратора | Получите свой ID командой `/id` в личном чате и запишите его в `.env`. |
| `ModuleNotFoundError` | Не установлены зависимости или использован другой интерпретатор | Активируйте `.venv` и выполните `python -m pip install -r requirements.txt`. |
| В `/status` написано «OBS недоступен» | OBS выключен, WebSocket недоступен, неверный адрес/порт, сетевая ошибка | Проверьте OBS и настройки в `/obs`; используйте «Проверить связь». При запуске на другом устройстве `127.0.0.1` указывает на **само это устройство**, а не на компьютер с OBS. |
| Ошибка аутентификации OBS | Пароль WebSocket неправильный либо параметры безопасности OBS изменились | Измените пароль через `/obs`, повторите проверку подключения. |
| В `/setup` нет источника | Нет доступного входа типа `browser_source` в активной коллекции | Создайте/проверьте Browser Source в OBS, затем обновите список. Другие типы входов не подходят для назначения мониторинга. |
| Автоматика не включается | Не выбраны объекты, коллекция изменилась или текущая сцена не основная | Проверьте `/setup`, выберите основную сцену в OBS, повторите `/auto on`. |
| «Назначения OBS недействительны» | Сцена/источник переименованы, удалены или сменена коллекция | Заново назначьте источник, основную сцену и сцену паузы в `/setup`. |
| Сцена не переключается при плохом кадре | Мониторинг выключен, OBS не на основной сцене, пороги не достигнуты, правило выключено или сработало аудиоисключение | Проверьте `/status`, `/rules`, `/check`, количество `bad_checks` и включённые детекторы. |
| Бот не возвращает основную сцену | Ещё не достигнут `good_checks`, кадр остаётся плохим или автоматике больше не принадлежит сцена паузы | Проверьте `/status` и качество кадра через `/snapshot`; при необходимости выберите сцену вручную и включите автоматику снова. |
| `/check` не находит зависание | Команда анализирует только один независимый снимок | Включите `freeze` в `/rules` и наблюдайте результаты фонового мониторинга на последовательности кадров. |
| Аудиоисключение не срабатывает | Нет показаний, неверный источник, низкий пик, `mute`, не запущены события измерителя | В `/rules` выберите нужный источник и нажмите «Проверить звук»; проверьте громкость и `audio_threshold_db`. |
| Не приходят уведомления | Бот не может написать администратору, действует антиспам или Telegram запрещает отправку | Откройте личный чат с ботом, проверьте `/notifications`; учтите, что события восстановления и трансляции обновляют статус без нового push. |
| Кнопка `/stream` не запускает эфир | Не выбран профиль для старта или OBS уже вещает/ведёт запись при необходимой смене профиля | Выберите профиль в `/stream`, убедитесь, что OBS может вещать с выбранными в нём параметрами, затем подтвердите запуск. |
| Изменение профиля/коллекции приводит к выключению автоматики | Это штатное поведение | Проверьте назначения, снова выберите основную сцену, затем включите `/auto on`. |

## Автоматика не включается

В `/setup` сначала подтвердите назначения. `source_name` должен быть **Browser Source**, `normal_scene` и `fallback_scene` — **двумя разными существующими сценами**. Сохранённое имя коллекции должно совпадать с активной в OBS.

Для `/auto on` недостаточно просто выбрать сцены в настройках: **в момент включения OBS должна показывать основную сцену**. После переназначения объектов автоматика отключается намеренно.

Если сцена была переключена вручную через `/scenes`, автоматику нужно включить повторно. Если стороннее управление переключило сцену, пока бот владел сценой паузы, автоматика также отключается, чтобы не спорить за управление OBS.

## Скриншот есть, но проверка неверна

Проверьте `/snapshot`, а затем `/check`. Анализ производится не по всей композиции OBS, а по выделенному Browser Source, обрезанному по `monitor.crop`. По умолчанию отсекается по 5% по каждой стороне. Порог чёрного и доля чёрных пикселей, дисперсия яркости и условия зависания указаны в [конфигурации](CONFIGURATION.md#проверки-изображения).

Если вокруг видео есть рамки, титры или чёрные полосы, попробуйте скорректировать `crop` в `settings.json` **при остановленном приложении**. Для живого потока, у которого могут быть полностью статичные кадры, включение `freeze` требует особенно аккуратной настройки времени и порога различий.

## Нет данных аудио

Для проверки аудиоизмерителя необходим живой сигнал выбранного источника. `/rules` → «Проверить звук» показывает, приходят ли события от OBS, есть ли показания нужного входа и достигается ли порог.

Не путайте уровень сигнала и положение регулятора громкости OBS: бот использует **фактически измеренный** пик. Заглушённый источник (`mute`) не разрешит проблемное изображение. Если связь с измерителем не установилась или источник отсутствует в его сообщениях, исключение не применяется.

## Сообщения о связи с OBS

При сетевой ошибке OBS бот сохраняет соответствующее состояние и увеличивает паузу между попытками до **не менее 30 секунд**. После восстановления соединения статус администраторов обновляется. Проверьте доступность сервера WebSocket и устойчивость соединения; перезапуск бота не является обязательным способом восстановления связи.

## Проблемы с уведомлениями

Бот пытается закрепить обновляемое сообщение у каждого администратора. Отдельные временные сообщения об ошибках/паузе ограничены `cooldown_seconds` и удаляются после `ttl_seconds`. Telegram может запретить закрепление или удаление сообщения; основная логика мониторинга от этого не зависит.

Если пользователь удалён из администраторов, бот пытается снять закрепление и удалить его прежнее статусное сообщение.

## Безопасность и данные

- Не публикуйте `.env` с токеном Telegram.
- Не публикуйте `settings.json`: он содержит пароль OBS WebSocket в открытом виде.
- Не публикуйте `notifications.json`: там могут быть Telegram ID, ID сообщений и тексты событий. В исходном `.gitignore` **этот файл не перечислен**.
- Не предоставляйте OBS WebSocket общедоступный сетевой доступ. Предпочитайте изолированную или защищённую сеть.
- Для новой установки не используйте заглушки из `.env.example`.

## Синтаксическая проверка

Если есть подозрение на повреждение исходников, без запуска Telegram и OBS можно проверить, компилируются ли Python-модули:

```bash
python -m py_compile main.py obs_client.py detector.py
```

Эта команда **не** проверяет реальную связь с OBS, Telegram, настройки сцен и поведение детектора.
