# OBS Control

**OBS Control** — Telegram-бот для управления [OBS Studio](https://obsproject.com/) через OBS WebSocket и автоматического переключения сцен при проблемах с изображением в **Browser Source**.

Бот получает кадры выбранного браузерного источника, проверяет их по настраиваемым правилам и при обнаружении проблемы переключает OBS с основной сцены на сцену паузы. Когда изображение восстанавливается, бот может вернуть основную сцену. Управление и настройка выполняются в личном чате Telegram.

## Возможности

- Обнаружение почти чёрного, однотонного и зависшего изображения; настройка порогов и периодичности проверки.
- Необязательное **аудиоисключение**: проблемный кадр не вызывает переключения, если выбранный аудиоисточник OBS передаёт звук выше установленного порога и не заглушён.
- Переключение на резервную сцену и возврат на основную по результатам проверок.
- Просмотр состояния OBS, получение снимка контролируемого Browser Source и ручная проверка кадра.
- Ручное переключение сцен, изменение видимости элементов активной сцены, обновление одного или всех Browser Source в текущей коллекции.
- Выбор профилей и коллекций сцен; запуск и остановка трансляции OBS с подтверждением действия.
- Настройка подключения OBS, назначений, правил и уведомлений из Telegram.
- Разграничение доступа (`viewer`, `operator`, `admin`), заявки новых пользователей и управление ролями.
- Обновляемое статусное сообщение для администраторов, оповещения об ошибках и переключениях, автоматическое удаление временных уведомлений.

## Требования

- **Python 3.10+** и `pip`.
- Запущенная **OBS Studio** с доступным OBS WebSocket; адрес, порт и пароль подключения (в примере порт — `4455`).
- В OBS: хотя бы один **Browser Source**, основная сцена и **другая** сцена для паузы в одной коллекции.
- Токен Telegram-бота и числовой Telegram ID первоначального администратора.
- Доступ к OBS WebSocket с компьютера, где запущен скрипт, и возможность связи с Telegram.

Зависимости перечислены в [`requirements.txt`](requirements.txt). В архиве **нет** Dockerfile или конфигурации Docker Compose: предусмотрен прямой запуск Python-приложения.

## Быстрый запуск

Выполните команды из каталога проекта:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
```

В файле `.env` укажите реальные значения:

```dotenv
TELEGRAM_BOT_TOKEN=123456789:your_real_bot_token
ADMIN_TELEGRAM_ID=123456789
```

Запустите бот:

```bash
python main.py
```

На Windows используйте `py -3 -m venv .venv`, `.venv\Scripts\Activate.ps1`, `Copy-Item .env.example .env` и `py main.py` (PowerShell).

При первом запуске создаётся локальный файл `settings.json` на основе [`config.example.json`](config.example.json); при необходимости бот восстановит настройки из старого `config.json`. Скрипт работает в режиме Telegram **long polling** и должен оставаться запущенным.

Подробности: [установка и первый запуск](docs/INSTALLATION.md).

## Краткая инструкция по использованию

1. Откройте личный чат со своим ботом в Telegram, отправьте `/start` или `/menu`.
2. Выберите **«🔌 Подключение OBS»**, задайте адрес, порт и пароль WebSocket, затем нажмите **«🔍 Проверить связь»**.
3. В **«🎯 Назначения»** выберите существующий **Browser Source**, **основную сцену** и **сцену паузы**; проверьте назначения. Бот получает списки непосредственно из OBS.
4. В **«⚙️ Правила»** настройте необходимые проверки изображения. По умолчанию включена проверка чёрного кадра, а проверки однотонности и зависания выключены.
5. Переключите OBS на **основную сцену**. Откройте **«🤖 Автоматика» → «✅ Включить»** или отправьте `/auto on`.
6. Проверяйте состояние через `/status`, результат анализа через `/check` и снимок контролируемого источника через `/snapshot`. Остановить автоматическую смену сцен можно через `/auto off`.

Ручной выбор сцены через бот **отключает автоматику**. Если назначение источника или сцен изменено, перед повторным включением проверьте настройки. Для работы автоматического контроля OBS и бот должны оставаться запущенными.

### Часто используемые команды

| Команда | Действие | Минимальная роль |
| --- | --- | --- |
| `/start`, `/menu` | Открыть меню | Авторизованный пользователь |
| `/id` | Показать собственный Telegram ID в личном чате | Любой пользователь |
| `/status` | Показать состояние OBS и автоматики | `viewer` |
| `/scenes` | Выбрать текущую сцену OBS | `operator` |
| `/sources` | Включить/выключить видимость элементов текущей сцены | `operator` |
| `/check`, `/snapshot` | Проверить кадр / получить снимок Browser Source | `operator` |
| `/auto on`, `/auto off` | Включить/выключить автоматику | `operator` |
| `/refresh`, `/refreshsources` | Обновить контролируемый Browser Source / выбрать источники для обновления | `operator` |
| `/obs`, `/setup`, `/rules` | Настроить подключение, назначения и проверки | `admin` |
| `/stream` | Управлять трансляцией OBS | `admin` |
| `/users` | Управлять пользователями и заявками | `admin` |

Все команды и сценарии: [руководство пользователя](docs/USAGE.md).

## Конфигурация и файлы

| Файл | Назначение |
| --- | --- |
| `.env.example` | Пример переменных для запуска |
| `config.example.json` | Исходные значения конфигурации |
| `settings.json` | Создаётся при запуске: подключение OBS, назначения, роли, уведомления, выбранный профиль вещания |
| `state.json` | Создаётся при изменении состояния: автоматика, признак переключения на сцену паузы и правила детектора |
| `notifications.json` | Создаётся для хранения статусных сообщений, истории событий и очереди удаления оповещений |
| `main.py` | Telegram-бот, управление и цикл мониторинга |
| `obs_client.py` | Работа с OBS WebSocket, сценами, источниками, потоком и аудиособытиями |
| `detector.py` | Анализ изображения из снимков OBS |

Файлы `settings.json`, `state.json` и `notifications.json` относятся к работающему экземпляру и не должны попадать в публичный репозиторий. **Обратите внимание:** в исходном `.gitignore` из архива **не указан `notifications.json`**, поэтому при публикации его нужно исключить отдельно. `settings.json` хранит пароль OBS WebSocket **в открытом виде**.

## Ограничения

- Контролируется **один назначенный Browser Source**. Снимки и оценки берутся из OBS WebSocket, а не из прямого подключения к URL видеопотока.
- Автоматика не создаёт сцены и источники: объекты должны существовать в OBS заранее.
- Платформа вещания, сервер и ключ трансляции настраиваются **в профилях OBS**; бот выбирает профиль и управляет запуском/остановкой потока.
- Работа с Telegram организована через polling; веб-панели и конфигурации Docker в предоставленном проекте нет.

## Проверка

В архиве отсутствуют автоматизированные тесты. Для полноценной проверки необходимы доступные OBS и Telegram-бот; базовую проверку синтаксиса Python можно выполнить командой:

```bash
python -m py_compile main.py obs_client.py detector.py
```
